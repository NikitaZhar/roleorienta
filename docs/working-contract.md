## 0.2. Актуальность корневого README.md (обязательно)
Корневой `README.md` — краткая внешняя витрина проекта. Он поддерживается в актуальном состоянии при работе над **любым** кодом: если изменение затрагивает то, что заявлено в README, README обновляется в рамках той же задачи (часть Definition of Done), а не откладывается на потом.

README обновляется, **когда — и только когда — изменение затрагивает** хотя бы одно из:
- что за проект и что он делает (назначение, ключевой набор функций, область);
- технологический стек или версии (язык, фреймворк, БД, брокер и т.п.);
- архитектуру или набор развёртываемых модулей/сервисов;
- шаги сборки, конфигурации или локального запуска (команды, скрипты, порты, обязательные переменные окружения);
- статус проекта или сводку стадий/roadmap, приведённую в README;
- endpoints, точки входа или примеры, процитированные в README.

README **не требует** обновления, когда изменение внутреннее и ни один из пунктов выше не затронут — например, рефакторинг без изменения стека/архитектуры, внутренний багфикс, изменения только в тестах, или новые детали, которые живут в `docs/` и не меняют сводку README.

Правила:
- README держится на уровне сводки; глубокие детали остаются в `docs/technical-design.md`, а текущий статус — в `docs/project-notes.md`. В README правится только сводка, со ссылками на подробности.
- Если изменение затрагивает стек, шаги сборки/запуска или статус — правка README **блокирующая**: задача не считается завершённой, пока README не отражает реальность.
- Критерий при сомнении: «введёт ли теперь README в заблуждение того, кто читает его впервые?» Если да — обновить.
