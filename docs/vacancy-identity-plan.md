# Одна вакансия — одна запись

## 1. Задача и мера

**Зачем пользователю.** Пользователь видит одну и ту же вакансию два и больше раз: добор с profesia.sk рядом с
вакансией системы найма работодателя, объявление profesia.sk на портале и на странице компании, копии и повторы
объявлений одного работодателя. Число вакансий и мера «видно N из M» завышены (Accenture: 48 открытых при 26 в Workday).
Признаки не зависят от страны и числа источников.

**Мера.** `target/s276-measure.sql` — 126 пар публикаций выборки `target/s276-sample.txt` с решением разбора (§2):
86 «одна», 40 «разные». Публикация пары задана источником и внешним id (повторяемо после любой склейки); пары 155–160 —
по номеру объявления profesia.sk: все открытые публикации с этим номером в одной вакансии (открытых меньше двух —
пара закрыта, признак не проверен). Успех — нет расхождений
среди пар, у которых обе публикации открыты, и закрытых пар не больше 13 (10 %); больше — разбор, почему закрылись. До
срезов мера — точка отсчёта.

**Сначала — проверка записи (раздел 0 меры).** В выборке последнее подтверждение публикаций портала и добора —
2026-11-06, у остальных — 2026-11-09; одно объявление портала (пара 151, PCA Slovakia) снято на портале, а у нас
открыто. Предположение: общий список портала не обновляется с 06.11, и `portalFresh()` выключил добор. Если так — это
отдельная остановка ядра: её причина выясняется и устраняется до срезов, иначе мера покажет закрытия, а не склейки.

## 3. Причины (проверено по коду и выборке; §274, §275)

1. «Та же вакансия» решается только при записи новой публикации; записанные раньше вакансии не пересматриваются
   (DHL; Accenture — доска связана с компанией позже, §266).
2. Признак публикации не узнаёт тот же номер profesia.sk у разных провайдеров и хостов (в ключе — провайдер) и адрес с
   сессионным параметром (`search_id` кадровых страниц `*.profesia.sk` меняется при каждом чтении).
3. Объявление добора не сравнивается с источниками компании (`findNeighbourPostings`), в обе стороны.
4. Внутри одного источника по названию не склеивается (`taken`), а портал собирает объявления с нескольких площадок, у
   работодателей бывают копии и повторы.
5. Ключ названия `same_title` удаляет скобки (в них бывает место или вид работы) и нелатинские буквы.
6. Место сравнивается строкой, которую каждый источник пишет по-своему.
7. Девять механизмов решают «та же вакансия» по-разному: фильтр добора `NEW_TO_COMPANY` закрывает и создаёт заново
   (карусель, потеря «то же название в другом городе»), склейка по кнопке (§268) — отдельное правило, V100 разделяет то,
   что склейка может вернуть.

## 4. Определение «та же вакансия»

**Работодатель публикации** — компании её источника с ролью `EMPLOYER`; у публикации добора — компания объявления
(`profesia_offer.company_id`; источник добора с компанией не связывается — показатели и job-api не меняются). Без
компании и у доски группы (`GROUP`) — только признаки 1–3.

**Признаки по порядку; первый сработавший решает.**

1. **Номер объявления profesia.sk** — из внешнего id `profesia:N` или адреса `…profesia.sk/…/ON`. Сравнивается у всех
   открытых публикаций, без отбора по работодателю (номер однозначен сам по себе; закрывает и пару источника `name:` и
   источника по IČO одного работодателя).
2. **Адрес без сессионных параметров** (`search_id`, `utm_*`, `source`, якорь; хост без `www`, без регистра) — у всех.
3. **Провайдер + хост + id доски** (как сейчас, §139): DHL. У Workday id — внешний id без суффикса копии `-N`
   (`…_1205038` и `…_1205038-1` на сайтах `acjobsite` и `wfmathpe` одного хоста HPE), только при равных ключах
   названия (у Accenture `R00333406-1` без пары — суффикс не основание сам по себе).
4. **Кнопка отклика** — у одного работодателя:
   (а) кнопка ведёт ровно на одну открытую публикацию с тем же ключом названия (правило §270);
   (б) кнопки двух публикаций ведут на один адрес, ключи названий равны и места не разные по 5а (пара 114; общая
   страница вакансий работодателя с разными городами — не основание).
   **Запрет:** публикацию, кнопка которой ведёт на другую открытую публикацию работодателя с другим названием, признак
   5 ни с чем не склеивает (пара 99).
5. **Название и место** — у одного работодателя, в том числе в одном источнике:
   - **ключ названия** (новая функция `vacancy_title_key`; `same_title` остаётся для показателей и потерь): без
     регистра и диакритики, кириллица — транслитерацией в латиницу, без пометок пола и зарплаты (как `same_title`) и без
     скобок с правовой формой («(TOBI TEAN s.r.o.)»); **прочий текст в скобках сохраняется**;
   - **места публикации**: текст в скобках убирается («Slovensko (Práca vyžaduje cestovanie)» → Slovensko, «Senec
     (Logistické centrum)» → Senec); части по «;»; у портала (вид «Obec - Okres») — часть до « - »; у прочих — части по
     «,»; часть с номером дома или почтовым индексом («Hlavná 19», «Obchodná 2889/8») — не город; без двухбуквенных кодов; «okres X» → X; «Bratislava-…», «Bratislava I–V» →
     Bratislava, «Košice-…», «Košice I–IV» → Košice. Из частей — **города**, **края** («… kraj») и **общие** (страна:
     Slovensko, Slovakia, Slovenská republika и соседние страны; удалённая работа: «Práca z domu», «Home office»,
     «Remote»; пусто) — общие не место;
   - **5а** — у обеих есть города: одна вакансия, если города пересекаются, иначе разные; у обеих нет городов, но есть
     края: одна, если края пересекаются, иначе разные (пара 6: края Halo reality не пересекаются);
   - **5б** — иначе (у одной или обеих только общее место, или город против края): одна вакансия, если у работодателя
     ровно две вакансии с этим ключом названия — эти две (Accenture, Lugera, пары 127–131); больше — разные (O2,
     «Lekár záchrannej služby», Dobré reality).

**Порядок применения.** Сначала признаки 1–4 и 5а — образуют группы; затем 5б считает вакансии уже по группам (после
склейки Workday, портала и добора Accenture это две группы, а не три записи). При записи новая публикация, не
присоединённая признаками 1–5а, считается своей группой.

**Решение владельца (2026-11-09, принято).** Одно название и одно место у одного работодателя — **одна вакансия для пользователя**:
копии (PEMIAN, Spilatex), повторы (TRANSFER), объявление биржи труда и работодателя (Vertiv), несколько заявок под
одним названием (ZF, Freudenberg). Все публикации и ссылки остаются в вакансии. Правило §260 «5 × Operátor výroby
одного списка — разные» отменяется.

## 5. Как применяется

- **Ключи публикации** — номер profesia.sk, адрес, ключ названия, места (массив) и признак «только общее место» —
  считаются при записи и хранятся у публикации (`job_posting`, миграция с индексами; для накопленных — заполнение
  миграцией). Функции ключей — в БД, одни для job-worker и меры.
- **Кадровая страница**: внешний id и адрес — без сессионных параметров (`search_id`, `utm_*`, `source`) — вместе с
  записью по §4 (срез 2), не раньше: новая публикация присоединяется к вакансии прежней (признаки 1–2, свой источник
  тоже кандидат), прежняя получает отсутствие и закрывается через 3 чтения — вакансия, отметки и выдача сохраняются.
- **При записи** (`PostingRecorder`): кандидаты — открытые публикации всех источников работодателя, включая свой
  источник, и признаки 1–3 у всех; решение — §4. Заменяет `SameVacancy.byTitle`, `taken` и ограничение «не свой
  источник».
- **Пересмотр раз в час** — вакансии работодателей, у которых с прошлого прохода появилась публикация
  (`job_posting.first_seen_at`), изменились название или место (запись в `vacancy_revision`) или появилась связь
  источника с компанией (`company_source.found_at`); полный проход всех открытых — первый, раз в неделю (компания
  объявления profesia.sk, найденная позже, без отметки времени) и при смене версии функций ключей. Группы по §4 склеиваются в вакансию с меньшим id; перенос публикаций, истории, выдачи, сводки и отметок —
  как в `VacancyMergeRepository` (§268); название и ссылка оставшейся вакансии пересчитываются по главной публикации
  (первая не с profesia.sk, кадровая страница `*.profesia.sk` — как profesia.sk); сопоставление — сброс
  `match_version` у оставшейся. Партия — 50 работодателей, своя транзакция с исключительной блокировкой записи
  (`VACANCY_WRITE`); отметка прохода — время его начала. Заменяет склейку по кнопке (`VacancyMergeRepository`,
  `EmployerLinkSources`): кнопка — признак 4.
- **Добор**: `GAP` остаётся (какие страницы читать и что ушло из карты сайта — нагрузка на profesia.sk не меняется);
  снимается `NEW_TO_COMPANY` — объявление добора записывается и присоединяется по §4 (нет карусели и потери «то же
  название в другом городе»). Перескок добор ↔ портал закрывает признак 1 при записи: новая публикация с тем же номером
  присоединяется к прежней вакансии, выдача не повторяется.
- **Журнал склеек** `vacancy_merge`: оставшаяся вакансия, присоединённая, признак, время, перенесённые публикации и
  прежние отметки пользователей присоединённой (для разделения). **Разделение** — скрипт `ops/` по журналу (публикации
  и отметки возвращаются в прежнюю вакансию), пара записывается в «не склеивать» (`vacancy_merge_block`), пересмотр её не
  склеивает. Кнопки в интерфейсе нет.

## 6. Срезы

1. **Ключи** — функции `vacancy_title_key`, мест, номера, адреса; поля и индексы публикации, заполнение накопленных.
   Поведение записи и склейки не меняется (внешний id кадровой страницы — в срезе 2). Тесты — пары таблицы §2: ключи «одна»
   дают общий признак, «разные» — нет, включая ловушки (скобки, кириллица, общие места, края, Obec - Okres, районы
   Bratislava, много мест). Проверка — мера (точка отсчёта), заполнение ключей на всех публикациях.
2. **Запись по §4** — `PostingRecorder` и кандидаты; кадровая страница без сессионных параметров во внешнем id.
   Уточнено при срезе (стенограмма §279): ссылка из кнопки отклика у новой публикации при записи ещё неизвестна
   (читается после записи), поэтому объявлениям profesia.sk (портал, добор) при записи — только признаки 1–3, по
   названию и месту их склеит пересмотр (срез 3); `NEW_TO_COMPANY` снимается в срезе 3 вместе с пересмотром — иначе
   до него объявления добора, которые он отсеивает, стали бы новыми дублями. Ломаются и переписываются тесты:
   `SameVacancyTests` (`employerWithoutCompanyJoinsByName`, `doubtfulPostingKeepsOwnVacancy`), `ProfesiaOffersTests
   .offerKnownFromCompanyIsNotTaken`, `ReadSourceFlowTests`. Проверка — мера по новым вакансиям за сутки.
3. **Пересмотр раз в час и журнал** (сделано — стенограмма §280; пары считаются заново в каждой партии по всем
   открытым вакансиям, а не дельтой: подсчёт — секунды, признака изменения публикации в схеме нет) — склейка
   накопленного (и объявлений profesia.sk по названию и месту, с запретом кнопки), добор без `NEW_TO_COMPANY`, замена
   `VacancyMergeRepository` и правила V100,
   разделение скриптом. Переписывается `VacancyMergeRepositoryTests`. Проверка — мера целиком, Accenture (26 ± снятые
   с Workday), журнал первой склейки (число по признакам), пересчёт сопоставления после первого прохода.

## 7. Не входит (найдено при разборе, отдельно)

- Чтение кадровых страниц записывает не вакансии и чужие названия (maxins.sk «TPP», новости, автомобили, разделы IKEA)
  — шаг 2 §261.
- Вакансии вне Словакии без распознанной страны попадают в выдачу Словакии (HPE) — §148.
- Кадровые агентства (TRANSFER, Lugera) — отложено (§261).
- EURES (V101): вакансии общего источника закрыты, вернутся новыми записями без отметок — уже произошло; число
  отметок на закрытых вакансиях источника 10000000 — проверить.
