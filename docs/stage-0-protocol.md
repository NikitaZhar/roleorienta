# Протокол Этапа 0 — трек Workday (рынок SK/AT)

Записанный протокол проверки источника и рынка, как требует техдок §14 и ADR-17.
Цель Этапа 0: подтвердить, что автоматическое обнаружение находит настоящих
работодателей и их ленты, и зафиксировать правовое основание — **до** написания
адаптера. Паспорт ниже — рабочее допущение (владелец делегировал выбор ниши/рынка);
правится одной строкой, если что-то не так.

## 1. Паспорт пилота

| Параметр | Значение |
|---|---|
| Ниша | backend / JVM-инженерия (Java, Spring, PostgreSQL, cloud) |
| Рынок/территория | Словакия и Австрия (приоритетные) |
| Язык | пока только английский; мультиязычие (словацкий/немецкий, «english-friendly» A07) — следующим срезом |
| Первый вендор | Workday (энтерпрайз, де-факто открытый JSON API, без ключа) |
| Первый вход обнаружения | Индекс Common Crawl (URL `*.myworkdayjobs.com` → `tenant/site`); CT для Workday непригоден — см. п.3 |
| Область сравнения покрытия | Австрия — karriere.at (выбрана владельцем 2026-09-24, project-notes §82); Словакия — открыто; исследование 2026-09-25 (project-notes §88.2): profesia.sk, поиск `/praca/?search_anywhere=` robots.txt не запрещает, ждёт проверки условий использования (ранее: profesia.sk: robots.txt запрещает поиск и страницы компаний) |

Обоснование выбора вендора: Swiss Re / RBI — на SAP SuccessFactors, DT-IT — на
SmartRecruiters; ни один не на Workday. Workday взят первым как самый достижимый
энтерпрайз-вендор для проверки *механизма*; названные компании — следующими
треками (SuccessFactors/SmartRecruiters).

**Замечание по рынку (SK/AT):** распространённость Workday среди целевых
работодателей Словакии/Австрии ещё не проверена. Здесь Workday проверяет
*механизм* на любом достижимом тенанте; конкретный первый SK/AT-работодатель и его
вендор определяются отдельным подбором кандидатов и могут оказаться на другом
вендоре (напр. SuccessFactors). То есть трек Workday де-рискует движок, а привязка
к рынку SK/AT закрывается выбором первого тенанта (п.5).

## 2. Feasibility ленты Workday (подтверждено 2026-09-22)

Источники: dev.to (udaninn, «Workday job boards have a JSON API too»), jobo.world.

- **Список:** `POST {tenant}.wd{N}.myworkdayjobs.com/wday/cxs/{tenant}/{site}/jobs`,
  тело `{"appliedFacets":{},"limit":20,"offset":0,"searchText":""}`, без ключа.
  `limit ≤ 20` (больше молча возвращает пусто), пагинация `offset`, в ответе `total`
  и массив `jobPostings[]`. Поля: `title`, `externalPath`, `locationsText`,
  `postedOn`, `bulletFields`.
- **Деталь:** `GET {tenant}.wd{N}.myworkdayjobs.com/wday/cxs/{tenant}/{site}{externalPath}`
  (заголовок `Accept: application/json`) → `jobDescription` (HTML), `timeType`,
  `startDate` (YYYY-MM-DD), `jobReqId`, `country`, `additionalLocations`.
- Реальный тенант подтверждён: `workday.wd5.myworkdayjobs.com` (сайт `Workday`),
  структура URL `/{lang}/{site}/job/...` — живые DACH-вакансии.
- Ограничение: без CORS (server-side only — воркеру подходит).

## 3. Вход обнаружения

**Итог живой проверки 2026-09-23 (владелец):** для Workday основной вход — **индекс
Common Crawl**, а не CT.

- **CT (Cert Spotter), первая страница:** `200`, `x-ratelimit-limit: 10` (запросов в час
  без ключа); 100 выпусков → 300 имён, из них **140 wildcard** (`*.wdN.myworkdayjobs.com`)
  и **1** конкретный хост тенанта (`envops-gms.wd5`). Workday закрывает тенантов
  wildcard-сертификатами дата-центров → CT тенантов не перечисляет. `CertSpotterClient`
  (§52) остаётся для поддоменных вендоров (Recruitee, Personio и т.п.).
- **Common Crawl, коллекция `CC-MAIN-2026-39`,** `url=*.myworkdayjobs.com`, первые 3000
  URL → **116 досок `tenant/site`** (напр. `amgen/Careers`, `3m/Search`,
  `adventisthealthcare/AdventistHealthCareCareers`, `aig/japan`). `site` берётся прямо из
  пути URL; имена сайтов в основном нетиповые — словарный резолв (§53) их бы не нашёл.
  Результаты отсортированы по SURT (алфавит тенантов) → полный охват требует обхода
  страниц индекса по курсору. **Объём (проверено):** `showNumPages` →
  `{"pages": 5, "pageSize": 5, "blocks": 24}` — вся коллекция по шаблону Workday —
  **5 страниц** CDX (≈ 24 блока × ~3000 записей ≈ 70 тыс. URL); страница 1 начинается с
  `globalfoundries`/`gnw` (продолжение алфавита). Встречаются служебные URL
  (`/robots.txt`) и query-строки (`/External?q=...`) — отсекаются разбором.
  Нет совпадений → `404 {"message": "No Captures found for: ..."}`.
  **Надёжность CDX (проверено):** один и тот же запрос страницы 0 трижды — полный
  ответ (1.75 МБ, 12 202 строки, 12 с), оборванный на 65 536 байтах поток и `502`;
  клиент обязан отвергать оборванную страницу и повторять её (§55.5a), бюджет — B1.
  Шлюз индекса отдаёт `504` примерно через 10 с, а страница по умолчанию (5 блоков)
  отвечает ~12 с — поэтому страницы берутся мельче: `pageSize=1` (~3 тыс. URL,
  24 страницы на коллекцию, 0.8–8 с на страницу). Остаточные `502/504` (~1 из 6 запросов)
  случайны по страницам и проходят при повторе. Выборка — преимущественно US-работодатели: отбор SK/AT
  (по `locationsText`/`country` ленты) — на стороне гейта/нормализации, не входа.
- **Условия (A24):** данные Common Crawl — по их Terms of Use (открытый доступ); CDX-сервер
  общий и перегружаемый (отвечает 503) → бюджет страниц за проход и B1 обязательны;
  массовый обход — по колоночному индексу (техдок §5), для пилота достаточно CDX с
  бюджетом. Реализовано в `CommonCrawlIndexClient` (§54).

### 3.1 Certificate Transparency (исходный план; для Workday не подходит)

- Техника: перечислить поддомены `*.myworkdayjobs.com` из логов CT → каждый левый
  лейбл = кандидат-тенант → валидация ленты + **проверка принадлежности** (A11).
- **Источник CT — Cert Spotter (SSLMate) CT Search API** (выбран; `crt.sh` закрывает
  автоматических клиентов через `robots.txt`). Запрос:
  `GET https://api.certspotter.com/v1/issuances?domain=<domain>&include_subdomains=true&expand=dns_names`,
  пагинация `after=<id>`, `Retry-After`. Условия (A24): неаутентифицированный доступ —
  «для личного/оценочного использования, ограниченное число запросов в час» (годится
  для пилота); для реального объёма — бесплатный API-ключ (Bearer). Реализовано в
  `CertSpotterClient` (§52); для живого прогона воркеру нужен egress на
  `api.certspotter.com`. Censys — запасной вариант (требует ключа/аккаунта).
- **Хост → `tenant/site` (живая проверка 2026-09-23, тенант `workday.wd5`):** корень
  хоста отвечает `406` на любой GET/HEAD (UA curl, Apache-HttpClient, браузерный; с
  `Accept: text/html` и без) и **не редиректит** — узнать `site` из корня нельзя.
  `/<site>` и `/<locale>/<site>` → `200`; cxs-список `POST .../wday/cxs/workday/Workday/jobs`
  с UA `Apache-HttpClient/5.5 (Java/21)` → `200` (лента доступна нашему клиенту без
  особых заголовков). Решение: `site` определяется проверкой кандидатов по словарю
  прямо через cxs-ленту (`WorkdaySiteResolver`, §53); тенант с нетиповым именем сайта
  этим способом не определяется. Калибровка (там же): `site` **не чувствителен к
  регистру** (`Workday` = `workday`, `total=367`); несуществующий сайт → `404` с JSON
  `{"errorCode":"S21","message":"not found: Job_Posting_Site_ID=<site>"}` — штатное
  «не этот сайт» (так ответили `NoSuchSite123` и `External`).
- Живую демонстрацию перечисления в сессии ассистента выполнить не удалось (crt.sh
  заблокировал фетчер по robots); шаблон тенанта подтверждён реальным примером
  (п.2), сама техника CT — стандартная.

### 3.2 Отбор по рынку: фасеты Workday (проверено 2026-09-23)

- **Сигнала рынка в индексе нет:** из 131 доски на 6 страницах CDX лишь у одной в URL
  встречается SK/AT (индекс хранит в основном корни досок, а не вакансии).
- **Фасеты списка Workday:** тот же `POST .../jobs` (даже `limit=1`) возвращает
  `facets[]`, в т.ч. `Location_Country` — **все страны доски со счётчиками и `id`**
  (тенант `workday`: 370 вакансий, US 173, India 28, … Poland 15, Czechia 1, SK/AT — 0);
  `searchText` фильтрует на стороне Workday (`java` → 51). Названия стран
  **локализуются по `Accept-Language`** (`de-DE` → «Vereinigte Staaten») — запрос
  фиксирует `en-US`. Бывает вложенный фасет-группа (`locationMainGroup`).
- **Решение:** гейт рынка в `DISCOVER_EMPLOYER` по тому же запросу, что уже делает проверка
  ленты (§56) — без дополнительных обращений. Фильтр сбора по `appliedFacets` (id страны)
  — следующий срез.
- **Фильтр по стране работает (проверено 2026-09-23):** `appliedFacets: {"Location_Country":
  ["<id Польши>"]}` → `total 15` (ровно счётчик фасета); вакансии — «Poland, Warsaw» и
  «2 Locations» (многолокационные, одна из локаций — Польша). Значит, сбор может просить
  у Workday только вакансии рынка: id стран берутся из фасета того же ответа (они
  различаются по тенантам), `locationsText` для многолокационных не показывает страну —
  фильтровать по нему нельзя, только по фасету.
- **Тенанты без фасета стран (проверено 2026-09-23 на 4 досках из 18):** у тенантов с
  одной страной (`2020companies`, `aaaie`, `aba`, `abcsupply` — все US) фасета
  `Location_Country` нет вовсе; есть группа `locationMainGroup` → вложенный фасет
  `locations` со **всеми локациями работодателя** и счётчиками («Arizona - Home
  Teleworkers 12», у многострановых — «AUS.ACT.Barton», «Canada, BC, Vancouver»).
  Гейт в этом случае судит по локациям (слова-признаки рынка, §59).
- **Поиск `searchText` по стране неточен:** «Poland» → 15 (совпало с фасетом), «Austria» →
  1, хотя в фасете стран Австрии нет (совпадение в тексте вакансии) — как основной
  сигнал рынка не годится.
- **Результат прогона 2026-09-23 (§61):** из ~950 проверенных досок Workday (первые ~40 %
  алфавита тенантов индекса CC) вакансии в SK/AT есть у 44 (≈4,6 %): 34 по фасету стран
  (IQVIA, Hitachi, Medtronic, DXC, Flex, Danaher, AT&T — Slovakia 9, …) и 10 по локациям
  (Snap, Mastercard, Broadcom, Nike, Ecolab …). Ложные совпадения «Vienna, VA/WV/GA»
  устранены (§61). Workday как вендор для рынка SK/AT **пригоден**: это крупные
  международные работодатели с офисами в Вене/Братиславе.
- **Метрика Этапа 0:** доля досок Workday с вакансиями SK/AT = `CONFIRMED` / (`CONFIRMED`
  + `OUT_OF_MARKET`) по `provider_code='workday'` — прямой ответ на вопрос п.1
  о распространённости Workday у целевых работодателей.

## 4. Следствия для реализации (закреплено)

1. **Деталь обязательна на каждую публикацию** (в списке нет описания/зарплаты/языков)
   → N detail-вызовов на прогон → **бюджет/rate-limit источников (B1) обязателен до
   первого реального сбора.**
2. `postedOn` — локализованная display-строка, не дата; настоящая дата — `startDate`
   из детали. Нормализация дат берёт `startDate` (A06/A18).
3. Зарплата и языки — только из `jobDescription` детерминированным экстрактором
   (§6, ADR-13, A07/A09); у многих вакансий зарплата честно останется `unknown`.
4. **Принадлежность доски работодателю** (A2/A11): `tenant`-slug ≠ юрлицо;
   подтверждать по брендингу сайта / полям детали, не считать slug именем компании.

## 6. Критерий закрытия Этапа 0

Выбран первый тенант; его лента читается и содержит нужные поля; правовое основание
записано; источник CT выбран с зафиксированными условиями; определена площадка
сравнения. После этого — код: **гейт принадлежности (A2)** и **скелет
Workday-адаптера** за контрактом `SourceAdapter`.
